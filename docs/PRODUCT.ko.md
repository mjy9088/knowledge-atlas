# 제품 경험 및 인터페이스 요구사항

## 1. 정보 구조

**Knowledge node**는 개념·현상·법칙·모형·방법·문제·실험·데이터 등 대상 자체를 가리킨다. **Content unit**는 그 대상이나 관계를 설명·시연하는 독립 사용 가능한 자료다. **Relation**은 노드 사이의 특정 관계, **Source**는 외부 원자료, **Experience**는 실제로 읽고 보고 조작하는 웹 표현, **Projection**은 Experience의 한 경로를 재생한 출력물이다.

1:1로 대응하지 않는다. 한 개념에 여러 설명이 있을 수 있고, 하나의 경험이 여러 개념 사이 관계를 주로 설명할 수 있다. 외부 위키 문서 ID도 내부 노드 ID와 무조건 같지 않다. 문서 개편·분할·병합에 대비해 내부 ID는 안정적으로 유지한다.

주요 관계 유형: `mentions`(단순 언급), `broaderThan`/`narrowerThan`, `requiresForThisExplanation`(글마다 다를 수 있음), `partOf`, `instanceOf`, `derivesFrom`(특정 증명/모형), `appliesTo`, `contrastsWith`, `analogousTo`(동일성이 아닌 비유), `relatedTo`(기본값). 관계에는 근거·적용 맥락·검토 상태를 기록한다. 출처에 링크가 있다는 사실만으로 강한 의미 관계를 단정하지 않는다.

## 2. 기본 이용 흐름

- 관심 있는 키워드 검색 또는 지도의 항목 선택 → 읽기/시청각 해설 바로 시작.
- 본문 내 용어와 주변 노드를 클릭 → 가능한 경우 문맥 내 간단한 팝오버/확장 설명 → 필요하면 독립 항목으로 이동.
- 읽다가 시각화의 조건·가정·관측 범위 조작 → 결과·가정·단위·모형의 한계 확인 → 설명 모드로 복귀.
- 필수 개념은 막다른 과제나 선행 수강 잠금으로 만들지 않는다. `이 설명에 유용한 배경` 링크로 제공한다.
- 무엇이 알려져 있고 무엇이 모델의 근사·가설·미해결인지 시각적으로도 언어적으로도 명확하게 한다.
- 각 항목에서 출처와 마지막 검토 시점·상태·정정 내용을 열람할 수 있다.

## 3. 화면별 요구사항

### 3.1 탐색·검색

- 전체 분야를 소수의 고정 카테고리로만 가두지 않는다. 다국어 명칭/별칭 검색, 분야·관계 필터, 최근 방문(명시적 동의/클라이언트 보관 기준) 지원 가능.
- 검색 결과에는 제목, 아주 짧은 개요, 지원 표현(텍스트/인터랙티브/음성/영상), 검토 상태가 나온다.
- 거대한 힘 방향 그래프를 기본 탐색 UI로 강요하지 않는다. 목록·현재 노드 주변 관계·본문 하이퍼링크 중심의 접근성을 우선하고 전체 그래프 뷰는 선택적으로 제공한다.
- 이용자가 왔던 경로를 쉽게 되짚고 다른 분기로 이동한다.

### 3.2 콘텐츠 읽기/경험

- 본문은 처음부터 끝까지 정적 텍스트만으로도 핵심이 이해될 수 있어야 한다.
- 상호작용은 필요한 지점에 삽입한다. 의미 없이 모든 단계에 클릭/드래그 요구 금지.
- 장면에는 현재 가정, 입력값과 단위, 관찰 대상, 결과값, 모형 적용 범위와 불확실성 표시를 위한 API가 있다.
- 재생형 설명(음성/영상)과 탐색형 조작을 전환할 수 있다. 이용자가 조작할 때 설명이 일시정지되거나, 상태가 바뀌었음을 알리고 동기화한다. 상태 복원·초기화·전후 비교를 제공한다.
- 증명/계산은 실제 검증 가능한 엔진의 결과로 표시하고, 모델 텍스트를 계산 결과인 것처럼 제시하지 않는다.
- 키보드 접근, 자막/전사, 적절한 대비·리듀스드 모션, 모바일 레이아웃, 조작 없이 가능한 대체 설명은 기본 요건.

해설에서 조건을 바꾸는 것이 유용하면 그 화면에 편집 가능한 기본 전제·목표·변수를 제안한다. 변경값은 탐색 중 보존하고 명시적으로 예시 상태로 복원할 수 있어야 한다. 도표뿐 아니라 대사도 현재 입력과 계산된 근거를 따른다. 해당 규칙이나 설명이 적용되지 않으면 무효화 이유와 현재 결과를 보여주며, 변경 전 예시 해설을 병치하지 않는다. 구문 오류·지원하지 않는 입력에는 이전 결과를 남기지 않는다. 전제 추가와 긴 식은 편집 목록·본문의 독립된 스크롤로 수용하고 목표 입력과 이동 버튼이 겹치지 않게 한다. 같은 유형의 입력·모형·시각화는 공통 컴포넌트로 재사용하고, 전용 테스트 페이지는 이해를 추가로 돕는 경우에 제공한다.

‘이미 안다’는 건너뛰기에는 **어떤 지식을 알고 있다고 보는지와 어디로 이동하는지**를 버튼 가까이에 표시한다. 제목이나 tooltip만으로 범위를 숨기지 않는다.

### 3.3 근거·판본·권리 패널

- 주장에 연결된 원자료의 제목·저자·링크·판본·유효 범위·라이선스와 번역·수정 고지를 보여준다.
- `마지막 원자료 동기화`와 `마지막 내용 검토`는 다른 날짜로 표현한다. 원문이 바뀌지 않은 것이 현재 분야의 최신 합의라는 주장을 의미하지 않는다.
- 내용 상태: `draft`/`automatically_checked`/`human_reviewed`/`needs_review`/`deprecated`/`withdrawn`. `human_reviewed`도 과학적 무오류 보증 배지가 아니다.
- 이견이 있는 내용은 연구 견해/모형별로 구분한다. 모든 분야에 동일한 확실성 기준을 적용하지 않는다.

### 3.4 피드백

- 문단·장면·현재 상태·영상 타임코드를 지정해 오류/오해/사용성/오디오 피드백을 제공한다.
- 일반 이용자 제안은 승인된 과학 내용 변경 명령이 아니다. 검토 큐로 들어간다.
- 승인된 정정은 웹 판본에 연결되고, 영향을 받는 영상은 가능한 정정 안내를 제공한다.

## 4. 제작자(사람)와 에이전트 UI

사람 전용 전문 편집기를 처음부터 전부 개발하지 않는다. 하지만 **항상 사람이 직접 개입 가능한 구조**여야 한다.

초기 제작자 화면/CLI:
- 원자료와 그 변경 diff, 영향받는 Claims/Scenes/Projections 확인
- 장면 선택 및 동일 입력 상태에서 전후 비교
- 설명·코드·시각 파라미터·영상 이벤트의 직접 수정 또는 자연어 수정 지시
- 지켜야 할 변경과 바꿔도 되는 범위 명시(잠금·보존)
- AI 제안의 변경 이유/원자료 근거/검사/위험/비용 확인
- 부분 승인·거절·되돌리기 및 공개 승인

향후 전문 UI는 타임라인·씬 계층·변수/상태 인스펙터·캔버스 조작·키프레임·오디오 자막 등을 제공할 수 있다. 에이전트는 같은 구조화된 원본을 도구/API로 다뤄야 하며 화면 픽셀 위치 기반 제어만을 필수 경로로 삼지 않는다. 사용자 요구와 전문 편집기를 둘 다 지원하되 같은 데이터 모델을 공유한다.

## 5. 유튜브 projection UX

- 웹의 단순 녹화가 아니라, **같은 내용·모형·장면으로 만든 하나의 고정된 탐색 경로**다.
- 유튜브만 시청해도 각 영상의 주장은 완결된다. 웹에서만 중요한 근거를 공개해 시청자를 강제로 유도하지 않는다.
- 영상의 도입은 해당 지식의 맥락을 설명하기 위한 것이지 흥미를 끌기 위해 원래 사실을 과장하는 것이 아니다.
- 화면은 상호작용의 사용자 입력 상태를 영상 시간으로 투영한다. 임의의 AI 서술과 실제 시뮬레이션 결과가 어긋나지 않는다.
- 자막, 출처, 정정 링크와 승인된 웹 판본의 참조를 함께 내보낸다.
- 가능하면 웹과 같은 입력 필드·체크박스·선택 상태와 값 변화를 보여주어, 웹에서 조작·실험 가능한 항목임을 별도 설명 없이 유추하도록 한다. 영상은 그중 고정된 경로이며 실제 조작은 웹에서 한다. 시각 표현만으로 충분하지 않으면 짧은 안내를 보완한다.

## 6. 지원 깊이와 콘텐츠 밀도

하나의 주제에 '입문/심화'가 항상 별도 영상이어야 할 필요는 없다. 기본 내용과 필요에 따라 펼치는 증명·세부 모형·예외를 연결해 두고, 실제 사용자 경험에서 유의미한 분기가 확인되면 추가 판본을 만든다. 난이도 측면에서 어려운 개념이 나와도 학습 경로를 강제하지 않는다.

## 7. 첫 수직 경로의 UX 요구

`content/formal-logic/explosion`에서는 조작이 즉각적으로 결과를 바꾸고, 전제가 바뀌면 기존 증명이 무효가 되는 이유가 표시되어야 한다. 임의의 결론을 도출해 보이는 장면과 현실의 진실에 관한 이야기를 분리한다. 정적인 증명 전개를 읽을 수 있어야 하며, '모순이 없어서 이 방식으로 증명 불가능'을 '어떤 방식으로도 증명 불가능'로 표현하지 않는다.

**현재 구현 범위:** 단순한 HTML 시연·네비게이션. 원본 동기화, 전문가용 편집기, TTS, 상태 기록 피드백, 완전한 접근성 자동검사 등은 추가 구현 대상이다.
