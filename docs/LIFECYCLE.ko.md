# 지식 공급·수정·갱신 수명주기

## 1. 목표

많은 양을 지속적으로 제공하면서 원자료와 자체 콘텐츠의 오류·변경·노후화를 추적한다. **원자료 변경 감지 ≠ 내용 정확성 판단 ≠ 공개 변경 승인**이다. '원자료 링크가 살아 있음'과 '과학적으로 여전히 유효함'도 다르다.

## 2. 소스 어댑터 파이프라인

1. 출처 발견: 범분야 백과·공개 교재·데이터·원 논문 중 가용/권리/개정 이력/정확성 특성 기록.
2. 수집 허가: API 이용조건·로봇정책·쿼터·생성형 AI 이용 제한·라이선스·매체 권리 확인. 불확실하면 원문 수집/개작 보류하고 링크와 서지정보만 저장.
3. 판본 고정: `source id`, `canonical URL`, `revision/commit`, `retrieved_at`, 해시, 원문 참조 범위, 저자·license, exception 기록. 가능하면 합법적으로 저장된 스냅샷 사용.
4. 추출: 개념/명제/조건/데이터/관련 링크 후보. **자동 후보**와 출처에서 명시적으로 확인된 사실 구분.
5. 설명 생성: 원문 내용을 제한된 범위에서 변환, 새 비유/관계/실험은 생성자가 책임지는 새 주장으로 분리.
6. 시청각 명세: 적합한 경우에만 장면·모형·음성·애니메이션 생성. 원자료의 의미와 적용범위를 장면에 계승.
7. 검증: 의미·권리·모형·UI·오디오·시각적 결과, 사전에 승인된 기준 사례와 비교.
8. 출판: 주어진 manifest를 잠그고 공개. 모든 콘텐츠가 같은 성숙도일 필요는 없음.

## 3. 두 가지 변경 감지

**출처 변경 추적:** 위키의 rev/최근 변경, 교재 Git 커밋, 데이터 배포일, DOI 메타데이터 등을 이용해 기존 스냅샷과 비교. 변경 이벤트 유실 가능성 대비 정기 전체 대조 수행.

**외부 과학적 최신성:** 원문이 그대로라도 연구·정정·새 관측이 들어올 수 있음. 콘텐츠 유형별 재검토 주기를 분리한다. 형식수학 정리의 증명 상태와 관측과학의 최신 측정치를 동일하게 처리하지 않는다. 논문 철회/정정·공식 자료 갱신을 감시하되 ‘새 논문 한 편’으로 합의를 자동 교체하지 않는다.

## 4. 변경 분류 및 조치

| 이벤트 | 기본 처리 |
|---|---|
| 서식/링크 수정 | 영향 없는지 빠른 검사, 의미 차이가 없다면 기존 승인 유지 |
| 용어/표현 수정 | 의미 변화 비교, 번역/음성 재검토 후보 |
| 수치 업데이트 | 단위·집계 기준·오차/표본 확인 후 영향받는 데이터·차트·자막 갱신 |
| 정의/가정/결론 변경 | 관련 Claim과 Model/Scene/Projection 전체 영향 분석, 사람 검토 |
| 중대한 오류·철회·권리 문제 | 관련 공개 콘텐츠 표시 제한/경고/제공 중단 우선, 영향 범위 추적 |
| 두 원자료의 충돌 | 자동 단일화하지 않고 근거/시점/해석 분기 제시 |
| 수집 실패 | 최종 성공 판본·검토 날짜 보존, 자동 최신 표시 금지 |

변경 영향은 **생성 의존 그래프**에 따라 계산한다. 단순히 지식 그래프에서 2홉 내에 있다고 모든 페이지를 재생성하지 않는다.

## 5. 부분 재생성과 불변성

- 기본 단위: claim 설명 블록 → 연결 장면 → narration chunk → 영상 구간/자막. 변한 구간만 invalidation 하되 인접한 타임코드와 화면전환에 미치는 영향은 다시 계산한다.
- 기존 공개 원본을 덮어쓰지 않고 **새 후보 판본**을 만든다.
- 사용자/제작자의 승인된 변경은 별도 provenance를 가진 patch로 남긴다. 자동 재생성과 충돌 시 세 방향 diff(기존 승인, 새 소스, 생성 후보)를 제시한다.
- 같은 모델/템플릿의 수정이 여러 콘텐츠에 영향을 주면 샘플이 아니라 전체 영향 목록을 만들고 회귀 검사한다.
- 재생성 작업은 입력 해시 기반 캐시와 작업 ID로 중복 실행을 막는다. 무한 반복에 대해 예산·시도 횟수·중단 사유를 기록한다.

## 6. 출판 상태와 승인

`draft → candidate → automatically_checked → review_required / approved → published`.

- 과학적 주장 새 추가·큰 변경: 사람/전문가 검토 필요.
- 검증된 규칙에 따른 단순 표시 변환: 정책에 따라 자동 승인 허용 가능 (처음은 보수적으로).
- 콘텐츠 공개 및 라이선스 고지: 별도 출판 승인 또는 명시적 정책 필요.
- 심각한 오류는 published에서 withdrawn/deprecated로 전환 및 정정 안내.

**정확성 등급**을 숫자로 대충 하나 붙이는 대신 검사 출처와 범위 표시: 원문 대조, 모형 단위 검증, 전문가 검토, 사용자 피드백 등.

## 7. 운영·관측 지표

- 공개 가능한 결과물 1건당 AI 비용·인간 검토 시간
- source refresh lag, 의미 있는 변경을 공개 판본에 반영하는 시간
- 기한 초과/검토 필요 노드 수, 깨진 링크/출처 권리 미확인 수
- 반복 피드백 발생률, 승인한 수정이 이후 재생성에서 보존된 비율
- 모델/상호작용 구성요소별 사용 범위, 렌더 실패/재시도 비용
- 이용자 신고에서 실제 정확성 이슈로 확인된 건수

관여도·조회수는 UX 진단의 자료일 수 있으나 지식 채택/연구 결론을 자동 최적화하는 목적함수가 아니다.

## 8. 검증 가능한 초기 구현 요구

첫 번째 소스 레코드를 잠그고, sample claim이 이 source를 참조하게 한다. 콘텐츠 설명을 수정할 때 영향을 받은 장면·스토리보드 목록을 CLI로 출력하고, 변하지 않은 파일의 해시는 유지한다. 이후 실제 GitHub/MediaWiki/출판기 자동 추적을 붙인다.
