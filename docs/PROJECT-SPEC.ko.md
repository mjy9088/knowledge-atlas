# Knowledge Atlas — 통합 프로젝트 요구사항 및 구현 계획

> **문서 상태:** 구현을 시작하기 위한 self-contained 기준 문서. 작성: 2026-10-16.  
> **목적:** 이전 대화를 읽지 못하는 사람/AI 에이전트도 이 문서 하나만으로 프로젝트의 의도·기술적 구조·첫 작업·검수 원칙을 이해하게 한다.  
> **구현 현황:** 초기 Git 저장소, 실험적 첫 웹 장면, 모델 테스트·참조 검증·스토리보드 JSON·변경 영향 후보 출력까지만 완료. 실제 본편 웹 콘텐츠/영상 렌더/AI 자동 작업/출처 추적 서버는 미완성.

## A. 본래의 목적 — 제품의 정체성

**범분야 과학 지식(형식과학과 자연과학, 컴퓨터과학 및 관련 영역)의 공개된 자료와 연결을 바탕으로, 관심 가는 글을 클릭해 계속 읽어보는 위키의 재미에 좋은 시청각·상호작용 표현을 결합한 웹 기반 지식 환경을 구축한다.**

지식·관계의 정확성과 깊이를 유지한 채 방문자가 자율적으로 탐색하게 한다. 재미는 선정적 소개나 단순 보상 자극보다 이해·예상·반례·추론·실험·개념의 연결을 경험하는 **지적 유희**다. 사용자는 콘텐츠를 아무렇게나 한 편 골라 볼 수 있고, 끝내더라도 손해가 없으며, 관심이 생긴 관계를 계속 따라갈 수 있다.

제작 단계에서 제작자가 ‘흥미를 끌 소재’부터 추려 콘텐츠로 재구성하지 않는다. **지도상의 지식과 관계 및 소스 품질/콘텐츠 공백을 바탕으로 제작**한다. 큐레이션은 특정 영상/탐색 경로의 내용과 언급 수준·연결을 고르는 정도로 제한된다. 과도한 강제 커리큘럼·자극적 훅·조회수 최적화를 기본 전략으로 삼지 않는다.

**웹 콘텐츠가 canonical 원본이다. 유튜브 동영상은 그 웹 콘텐츠와 모델에서 선택한 상태 변화/탐색 경로를 자동 재생하고 음성·강조·편집을 더한 projection이다.** 별도 진리 원본이 아니며 웹과 주장·조건·출처를 공유한다. 영상만 봐도 해당 설명은 독립적으로 완결되어야 한다.

제작자는 과학 전 분야에 정통하지 않을 수 있다. 따라서 좋은 공개 자료를 원자료로 삼고 AI가 접근성·표현·영상화를 담당하며, 출처에 없는 새로운 주장과 시각화 모형의 진실성은 별도 검토한다. 원자료를 참고할 때 **무료 열람·개작 허가·상업적 재배포·AI 처리 허용 여부를 각각 따져야 한다.**

## B. 핵심 제품 요구사항

### 해설·실험·영상의 공통 표현 원칙

조건 변경이 의미 있는 경우에는 기본 제안값을 같은 해설 화면에서 바꾸며 실험한다. 사용자의 변경은 장면 이동으로 지우지 않고, 도표와 대사를 현재 입력에 맞추거나 적용 불가로 무효화한다. 변경 전 예시 해설은 별도로 남기지 않고 명시적 복원에서만 다시 보여준다. 영상에도 같은 입력/선택 형태와 상태 변화를 사용해 별도 설명 없이 웹의 실험 가능성을 유추하게 한다. 전용 실험실은 이해에 특별히 도움이 되는 경우에 추가하며 비슷한 주제는 공통 모형·입력·결과 컴포넌트를 재사용한다. 모든 항목에 조작을 강제하거나 상수·정의를 임의로 가변화하지 않는다. 구현 계약은 ADR 0008을 참조한다.

### 이용자

1. 검색/항목/본문 링크/주변 개념에서 출발해 자기 순서로 이동. 어떤 분기로 갈지는 강제하지 않는다.
2. 개념, 현상, 모형, 이론, 정리, 실험, 관찰, 계산, 데이터 등을 읽는 기본 설명과 선택적 장면이 있다.
3. 인터랙션은 지식 이해에 의미 있는 경우에만 제공: 변수 변경, 단계 전개, 가정 비교, 3D 구조 관찰, 증명 검토, 데이터 탐색 등.
4. 조작 중 해설 동기화를 정지/재개하거나 기준 상태로 복귀 가능. 상호작용을 사용하지 않아도 핵심을 이해 가능.
5. 개념 간 연결은 단순 연관/선행/특수화/적용/모형의 유도/대조/비유 등을 혼동하지 않고 맥락과 근거를 표시.
6. 무엇이 공리에서 증명되었는지, 모델에서만 성립하는지, 관측되었는지, 아직 미해결인지 명확히 표시.
7. 출처의 저자·판본·수정 정보·사용 조건, 마지막 동기화와 실제 검토 시점을 확인 가능.
8. 모바일·키보드·자막/전사·저동작 모드·대체 설명을 제공. 강제 인증/퀴즈를 핵심 경험의 진입장벽으로 두지 않는다.

### 제작자

1. 기존 교재/위키/데이터를 버전 고정하고 메타데이터/권리 확인 후 변환하여 지식 지도와 연결.
2. AI가 지식 내용과 별도의 시각화/시뮬레이션/음성/영상 편집 명세를 만든 뒤 실제 렌더 결과를 확인·수정.
3. 사람이 장면/문단/타임코드/상태를 선택해 자연어 피드백을 주거나 전문 UI에서 직접 수정 가능.
4. AI는 수정 diff·영향 범위·테스트를 제시하고 **승인된 개별 수정사항을 다음 생성에서도 보존**한다.
5. 반복 피드백으로 일반 규칙/컴포넌트/테스트를 만들되, 임의의 지역 피드백을 무조건 전역 규칙으로 승격하지 않는다.
6. 원자료의 변경과 과학적 최신성을 지속 확인. 변화한 실질 의존 부분만 후보 재생성·검토, 자동 공개 금지.
7. 웹과 영상, 음성과 자막, 시뮬레이션이 동일하게 승인된 주장/모형/판본에 묶인다.

## C. 그래프는 두 종류

**탐색을 위한 지식 그래프:** `Concept`, `Relation`, `Experience`와 `Source` 연결. 외부 위키의 링크는 기본 `mentions`로 수집하고, AI의 강한 관계 추론은 검토 후 승격한다. 순환 연결도 허용. 내부 개념 ID는 외부 페이지 ID와 분리한다.

**갱신·제작을 위한 의존 DAG:** `SourceSnapshot → SourceSpan → Claim/Model → ContentBlock → Scene/Narration → Projection/Publication`. 원자료가 바뀌면 이 경로로 영향받는 출력만 확인한다. 지식 그래프에서 의미상 인접하다는 이유만으로 재생성하지 않는다.

지식 원본이 넓어진다고 모든 노드에 자체 인터랙티브를 만들 필요는 없다. ① 확인된 자료 링크/정적 해설, ② 충분한 설명과 증거, ③ 상호작용이 있는 장면, ④ 영상 projection 등의 완료 정도를 별도로 관리한다.

## D. 콘텐츠 원본 데이터 계약

고정 ID와 버전이 붙은 다음 엔터티를 저장한다.

| 엔터티 | 필수 의미 | 핵심 요구 |
|---|---|---|
| `SourceSnapshot` | 원본 문서/데이터 특정 판본 | URL, revision/commit, 수집일, 해시(실제 저장 시), 저자·권리·본문 범위 |
| `Concept` | 지식 대상 | 내부 ID/다국어 이름/외부 ID와 동등성 확인 |
| `Relation` | 개념·주제 연결 | 관계 유형·근거·맥락·검토 상태 |
| `Claim` | 중요한 검증 대상 주장 | 정확한 범위·가정·원자료 위치·종류·검토 상태 |
| `Model` | 계산/증명/시뮬레이션 | 입력/출력/단위/범위/한계/회귀 테스트, 순수 함수 우선 |
| `ContentBlock` | 문단·설명 구성요소 | ID, claim refs, 번역/변환 출처, 설명 표현 |
| `Scene` | 시청각/상호작용 단위 | state/control API, 의미 요소 ID, claim refs, 시각 상태/대체 표현 |
| `NarrationChunk` | 해설의 작은 단위 | 본문·발음·음성·자막·동기화 메타데이터 |
| `Projection` | 영상/슬라이드 등 고정 경로 | scene/time/state/강조/카메라/오디오 이벤트 및 출력 버전 |
| `Feedback` | 수정 요구 및 해결 내역 | 대상 ID·정확한 당시 상태·기대 결과·수정 범위·불변조건·승인 |
| `PublicationManifest` | 공개된 일관된 판본 | 전체 content/model/scene/audio/source rights 버전·승인·검사 기록 |

필드 스키마 초안은 `packages/contracts/`를 참조한다. 초기 샘플 JSON은 간소한 최소 데이터이며 전체 계약은 차근차근 구현해야 한다.

### Scene API 불변조건

장면은 `getState()`, `setState(validatedState)`, `reset()`, (시간 기반 장면이면) `seek(timeMs)`를 제공하고 결과의 의미적 상태(`semanticElementIds`, 표시 값, warnings)를 검사기/에이전트가 얻을 수 있어야 한다. 영상 프레임을 시간 `t`로 독립 재현할 수 있도록 임의성은 시드로 고정하고 hidden history에 의존하지 않는다. UI/컴포넌트 구조는 자유롭게 구현 가능하며 현재 정식 라이브러리 선택은 잠정적이다.

콘텐츠의 **과학 모형과 표현 렌더러는 분리**한다. 인터랙티브 UI 입력과 영상의 시간 이벤트가 같은 모델을 호출한다. AI가 보이는 값이나 계산을 임의 서술로 꾸며내지 않는다.

## E. AI 제작·개선 작업 모델

```text
수집·권리 점검 → 판본 고정 → 개념·주장·조건 추출 →
한국어 설명 초안 → 시각화/음성/장면 명세 →
실제 구현·실행 → 내용·모형·브라우저·CV·오디오 검증 →
피드백→범위 한정 패치→비교/검사→승인 →
같은 판본의 영상 타임라인/자막/렌더 → 검수→공개 후보
```

- 코딩 에이전트는 구조화된 파일/API를 수정하고 검사를 실행한다. 에이전트가 특정 인지 구조에 맞는 의미적 레이어를 제공하되 사람이 직접 고칠 수 있는 전문 UI를 보장한다.
- CV 검증은 실물 프레임의 잘림·겹침·경계·강조·동기화 실패를 찾고, DOM/의미 요소·수치 검사·모형 정합성을 보완한다. **CV만으로 과학적 참을 보증하지 않는다.**
- 피드백 적용 범위는 scene/콘텐츠/표현패턴/전역으로 구분. 의도를 구조화하고 불변조건·승인된 패치를 재생성에서 보존한다.
- 큰 변경은 테스트 결과와 diff를 보이고 사람이 승인한다. 과학적 근거/정답 fixture를 수정하는 권한을 일반 코드 작성 에이전트와 분리한다.
- AI 생성 도중 외부 원문의 지시/스크립트를 실행하지 않는다. 격리 샌드박스, 승인된 호스트 도구, 작업비용·재시도 제한과 로그. 비밀·인증 정보를 출력물에 남기지 않는다.
- 원자료 업데이트는 새 후보 생성에 그치고, 공개는 별도 권한/정책을 거친다.

### 피드백 개선의 두 출력

**지역 수정:** 문제가 발생한 장면의 특정 값·타이밍·설명·화면에 대한 보호된 patch.

**재발 방지:** 충분히 반복 검증된 공통 제작 규칙·좋은 예시·회귀 fixture. 승인 과정과 예외 조건을 별도로 기록. 지역 피드백을 전역 정책으로 무조건 승격하지 않는다.

### 권장 검증 레이어

1. 근거/정의/가정·결론 일치, 출처의 신뢰와 권리 상태.
2. 모델/증명/단위/경계값 회귀 fixture.
3. 웹 기능·DOM·키보드·반응형·접근성 + 실제 캡처/CV.
4. 영상 분절/프레임 가시성/장면 상태·나레이션·자막 동기화/ffmpeg 검사.
5. 원본·피드백·공개 판본의 불변성과 회귀 보호.

## F. 지속 가능한 공급과 최신성

- 원자료별 adapter를 사용하여 초기 덤프/판본과 이후 변경 이벤트·정기 reconciliation 분리.
- 라이선스/약관/속도제한을 통과한 일부 원자료만 실제 복사/가공한다. 외부 개작이 불가하면 링크와 독립적인 서술만 사용.
- 원문 변경은 (표현·단위·수치·가정·결론·정정/철회·권리) 유형으로 분류. 의미 변화를 확인해야만 영향받은 claim/모형/장면/영상 명세를 candidate로 갱신.
- **현재 연구 상태**는 원자료 편집 이력만으로 보장하지 않는다. 안정된 정리와 새 관측 데이터를 다른 리뷰 정책으로 관리한다.
- 생성 영향과 공개 범위는 사용자 지식 그래프가 아닌 제작 의존 DAG를 활용. chunk-level regeneration, content-addressed cache, artifact manifest 및 롤백.
- 콘텐츠 수정과 source license notice를 동기화. 변경·정정·보류된 콘텐츠 상태가 이용자에게도 필요에 따라 노출.

## G. 권리 원칙과 초기 출처

우선 검토: 범분야 지식·개념 색인에 Wikipedia/Wikidata, 깊이 있는 교재에 LibreTexts 등, 분야별 연구 교육에 Science in School/Frontiers for Young Minds, 형식과학에 forall x: Calgary/Open Logic Project. 모두를 무조건 하나의 자유 라이선스로 취급하지 않으며 텍스트·이미지·음원·도표·소프트웨어 별로 권리 및 이용 약관을 확인한다.

- `forall x: Calgary`: https://forallx.openlogicproject.org/html/ . 2026-09-27 revision `c5cb415`를 표시하며 CC BY 4.0과 기여 출처를 명시. 본문 17장 자연연역 https://forallx.openlogicproject.org/html/Ch17.html
- `Open Logic Project`: https://openlogicproject.org/olp-license/ — 웹 본문은 별도 표시가 없는 한 CC BY 4.0. 실제 사용 범위에 따라 저자표시/수정 고지.
- `Wikidata`: https://www.wikidata.org/wiki/Wikidata:Licensing — 구조화된 데이터 CC0. Wikipedia 본문/미디어는 다른 조건.
- LibreTexts/각 기사 등: 제공자 플랫폼 전체의 라이선스로 개별 교재·이미지를 추정하지 않는다. 편집과 AI 처리 약관도 확인.

- 자체 저장소 코드·문서 전체에 어떤 공개 라이선스를 적용할지는 **아직 결정되지 않았다**.

## H. 첫 번째 수직 경로: ‘모순 폭발’

첫 주제는 과학 전반 콘텐츠 중 하나의 시험용 샘플이다. 제목 제안: **〈모순이 있으면 무엇이든 증명할 수 있을까?〉**. 실제 영상 5~8분 정도는 가설일 뿐 편집 제약 아님.

핵심 내용: 통상적인 고전 자연연역에서 `P`, `¬P`를 가정하면 `⊥`를 얻고, 폭발 규칙으로 임의 문장 `Q`를 얻는다. 이는 **해당 추론체계의 증명 가능성**을 말하며 현실의 Q가 참이라고 말하는 것이 아니다. 전제를 하나 제거했을 때 *이 경로가* 끊어진다고 하여 모든 경로에서의 증명 불가능성을 증명한 것은 아니다. 직관주의 논리 역시 보통 폭발을 허용한다. 이 사례는 ZFC의 일관성 조건과 연결될 수 있지만 CH 독립성을 증명하지 않는다.

최소 Scene: `P`/`¬P` 토글, 임의 결론 Q/R/S 선택, 단계별 도출, 상태 복원·재현, 출처·가정·한계 설명. 영상 projection은 동일한 Scene의 대표 상태 몇 개를 순서대로 재현하고, 별도 음성·강조·자막을 붙인다. 첫 피드백 F1(결론 전 시간), F2(증명과 현실 참의 혼동), F3(이미 승인된 수정 보호)를 실제로 처리한다.

현재 repo 샘플은 이 Scene의 무의존성 HTML/JS + 모델 테스트 + source/claim/scene/projection JSON + storyboard CLI다. 30초 placeholder timeline은 완성된 5~8분 영상이 아니며 **MP4는 아직 존재하지 않는다**.

## I. 초기 기술 구성 (교체 가능)

첫 실행 가능 샘플은 Node.js 22+ 무의존성. `npm run dev`, `npm run validate`, `npm test`, `npm run storyboard`, `npm run impact` 제공. Git 이력과 CI 설정 포함.

확장 시 후보: Astro + MDX(문서 중심 웹), React islands/Canvas/WebGL(장면), JSON Schema/Zod(계약), Playwright(조작·CV 비교), Remotion + FFmpeg(영상 projection), 별도 TTS·자막·오디오 분석, Git/DB-backed 버전 관리, 필요 시 워크플로 엔진. 단, **새 스택을 전체 교체 이유로 삼지 말고** 안정된 ID·원본 데이터·scene API·검증 기준을 보존한다. 특정 외부 렌더러의 조직 규모·상업 이용/자동화 라이선스도 확인해야 한다.

초기 Git 저장소 기본 구조:

```text
apps/web/         초기 인터랙티브 데모
apps/video/       향후 영상 렌더 어댑터
docs/             통합/세부 요구사항과 결정 기록
knowledge/        concepts + relations
sources/          소스 판본 및 권리 레코드
content/          승인 전 파일럿 콘텐츠, scene, narration, projection
packages/models/  과학적 계산/추론 모형
packages/contracts/ 데이터 계약 JSON Schema 초안
scripts/          validation, dev, storyboard, impact, release gate
feedback/         예제 수정 요청
tests/            기본 회귀 테스트
```

현재 기초 검사 결과는 3개 claim, 1개 scene, 5개 30초 placeholder segments를 대상으로 한다. **전체 제품의 구축·검증이 완료된 것이 아니다.**

## J. 액션 아이템과 의존 관계

**M0 기초 계약:** self-contained 문서, stable ID, source/claim/scene/projection JSON 예시, 오프라인 데모, validation/test, Git 관리. *부분 구현*.

**M1 첫 웹 Scene 정식화:** 조작/초기화/상태 재현, 모델/view 분리, keyboard/mobile/접근성, claim/source 패널, Playwright 검사. **다음 즉시 착수 항목**.

**M2 첫 영상 프레임:** scene/model 공유·deterministic seek·projection events·카메라/레이어/타이밍, 10~30초 실제 동영상 시범 출력, manifest.

**M3 첫 본편:** 실제 서술/해설/TTS or 녹음/자막/오디오 검증/영상 전환·강조/최종 MP4/권리 고지·정확성 검토.

**M4 피드백 루프:** 정확한 장면/상태/타임코드 피드백 → 범위 제한 수정·전후 비교·회귀 테스트·승인·보호 patch; F1~F3 검증.

**M5 공개/원자료 갱신:** source license audit, publication manifest, deploy, 변화된 원자료 영향 후보/승인/롤백/정정.

**M6 범분야 확장:** 물리적 수치 모형과 관측/생물·지구과학 과정 등 2~3종으로 테스트, 제공자별 수집기, 리뷰·큐, 전문 편집 UI, 비용/확장성 측정.

단계별 상세 DoD/체크리스트는 `docs/ROADMAP.ko.md`. 첫 제작의 핵심 완료 기준은 **한 장면이 웹과 영상에서 같은 의미로 재현되고, 피드백이 부분적으로 적용·보존되며, 원자료가 바뀌면 영향을 계산할 수 있는 것**이다. 조회수·영상 수·시각적 화려함만으로 성공이라 정의하지 않는다.

## K. 공개 품질 게이트

공개 버전은 다음 모두가 만족되어야 한다.

1. 사용 권한 확인 + 저자/판본/수정·라이선스 고지.
2. 주장과 근거를 지정할 수 있고, 새 생성 내용은 사실 검토를 통과.
3. 모형의 입력/단위/범위/기준 결과 검사.
4. 웹 조작·모바일·키보드·대체 설명과 화면 결과 검사.
5. 영상/음성/자막/장면/타임코드가 동일한 승인 내용을 가리킴.
6. 승인한 변경과 불변조건이 재생성에서 유지됨.
7. 출판 manifest가 잠겨 있고 정정/롤백이 가능.
8. 테스트와 인간 검토의 범위가 정확히 기록됨. 검사 미실시를 검사 통과로 표시하지 않음.

현재 `npm run release:check`는 콘텐츠 미승인/소스 정확판본 미동결/권리 검토 대기/실제 영상 미렌더 상태이므로 **실패하는 것이 정상**이다.

## L. 구현 에이전트에게 넘기는 첫 작업 지시문

> 이 저장소의 `AGENTS.md`와 `docs/PROJECT-SPEC.ko.md`, `docs/PILOT.ko.md`, `docs/ARCHITECTURE.ko.md`를 읽어라. 첫 구현 과제는 `docs/ROADMAP.ko.md`의 M1이다. 공개 데이터와 claim의 의미·출처를 임의 변경하지 말고, 현재 프로토타입의 proof 장면을 검증 가능한 모델/상태/렌더 구조로 정식화하라. `getState`, `setState`, `reset`, 추후 영상 seek 대응 인터페이스 및 브라우저 자동 검사를 구현하고, 시각/키보드/모바일·재현성을 확인하라. 변경 전후의 작동 증거와 아직 미구현인 기능을 정확히 기록하고 소규모 Git 커밋을 남겨라. M1과 무관한 전체 지식 그래프 구축, 인터랙티브 프레임워크 대규모 재작성, 완성형 영상 편집기를 동시에 구현하지 마라.

## M. 설계에서 앞으로 결정해야 하는 사항

- 공개 저장소 명칭/소유 주체/라이선스, 소스별 업스트림 저장·AI 학습/가공 조건.

기술적 선택은 재방문할 수 있지만, **원래 목적·출처/권리 추적·웹 원본·영상 projection·변경 보존·검증 분리**는 기반 원칙이다.
