# Scene 1 화면 피드백 안내

이 문서는 `experience:logic.explosion.ko`의 `scene:logic.explosion.proof`를 사람이 보고 조작하며 검토하는 안내다. 플랫폼 전체의 범위는 과학 전반이며, 이 논리 장면은 첫 구현 사례다.

## 화면에서 확인할 것

1. 처음 열었을 때 무엇을 조작할 수 있고 무엇을 보여주는지 이해되는가?
2. `P`, `¬P` 전제를 각각 빼고 다시 넣었을 때, 증명 단계와 설명이 함께 바뀌는가?
3. 결론을 `Q`, `R`, `S`로 바꾸었을 때 임의 명제 기호라는 뜻이 전달되는가?
4. 전제를 하나 뺐을 때 ‘결론이 거짓’이 아니라 ‘이 증명 경로가 구성되지 않음’으로 이해되는가?
5. 초기화했을 때 처음 상태로 돌아오는가? 시간 탐색이 제공되면 앞뒤로 이동한 상태와 화면이 일치하는가?
6. 좁은 화면과 키보드만으로도 입력·설명·출처를 읽고 사용할 수 있는가?
7. 출처·주장·판본의 검토 대기 상태와 관련 개념의 준비 상태가 명확한가?

화면, 문구, 배치, 조작감에 대한 의견만 주어도 된다. 상태 계약·모형 회귀·출처/권리·자동 검사는 에이전트가 별도로 확인하고, 사람의 화면 피드백을 과학적 승인으로 간주하지 않는다.

## 피드백 예시

> `¬P`를 끈 상태에서 안내가 너무 아래 있어 결론이 거짓이 된 것처럼 보인다. 결과 바로 아래에 안내를 보여주면 좋겠다.

> 휴대폰 폭에서 규칙 이름이 잘린다. 수식과 규칙을 두 줄로 보여주면 좋겠다.

관찰한 상태, 불편한 점, 원하는 결과를 알려주면 된다. 에이전트는 이를 장면 ID·당시 상태·콘텐츠 버전·수정 범위가 포함된 `Feedback` 기록으로 정리한다. 단순 의견 제출과 변경 승인, 과학적 내용 승인, 공개 승인은 각각 구분한다. 승인된 사람의 수정은 이후 변경에서도 보존해야 한다. 현재는 에이전트의 파일 기록과 변경 검토로 처리하며 자동 적용·보존 파이프라인은 아직 구현하지 않았다.

## 해석의 경계

- 전제 토글은 `P`의 진릿값 선택이 아니라 해당 전제의 사용 여부다.
- 이 장면은 특정 자연연역 경로를 보여주는 시범 모형이다. 일반 정리증명기나 현실의 참/거짓 판정기가 아니다.
- 전제 하나를 빼도 다른 증명 경로의 불가능성이 증명되지는 않는다.
- 화면의 30초 예시 상태 탐색은 기존 projection 초안의 상태를 직접 재사용한다. 0초에는 전제 없음/Q, 6초에는 두 전제로 Q, 12초에는 두 전제로 R, 18초에는 `¬P` 전제를 뺀 R, 24초부터는 `P` 전제를 뺀 Q를 보여준다. 자동 재생이나 완성 영상, 검토된 해설 타이밍이 아니다.
- 초기화는 두 전제로 Q를 보여주는 웹의 첫 상태다. 시간 탐색의 0초는 전제가 없는 storyboard 시작 상태이므로 서로 다르다.
- 원자료 판본·해시·권리 및 과학 전문 검토, 공개 승인은 별도 대기 사항이다.

구현 및 검사 증거는 [구현 현황](IMPLEMENTATION-STATUS.ko.md)에 기록한다. 화면 확인만으로 출처 검증이나 영상 파이프라인 완료를 표시하지 않는다.
