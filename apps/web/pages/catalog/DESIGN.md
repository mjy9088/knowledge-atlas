# Catalog design

## Purpose

The catalog lets readers scan questions and choose any explanation. Every active topic receives the same entrance treatment in registry order; no topic, article length or review maturity grants a larger tile or a special badge. It uses the [shared public design foundations](../../styles/README.md), rather than a catalog-specific palette.

## Composition

A white navigation header sits above the Gray 10 document canvas. A quiet metadata line, 40px question-led title and short 16px introduction precede the catalogue. The section title and a thin rule separate introduction from entrances. On narrow screens, the title is 32px and supporting copy 14px.

At the 960px logical desktop composition the grid has two equal columns; narrow screens use one. Gaps are 16px and tile padding 24px. Tiles have white surfaces, fine Gray 20 boundaries and square geometry. Each tile uses the same category 12px, title 28px, question 14px and payoff 12px hierarchy, in that order. Minimum tile height is 256px desktop and 240px narrow; grid rows stretch equally while preserving full, untruncated text. No tile spans columns or gains weight by topic. Normal document scrolling remains available, and the document has no horizontal overflow.

## Interaction and components

Each entrance is a canonical anchor with a full-title attribute and at least 44px target. Hover changes only the neutral surface tone; keyboard focus uses the shared blue inset outline. There is no lift, shadow, gradient, decorative hero or continuous animation. Reduced motion uses the shared foundation.

One labelled `#connections` section contains every entrance. The page-level draft notice after the grid preserves pending content/source/rights/publication status without ranking individual entries. Display title, opening question and final payoff come from the canonical catalog/article definitions.

## Verification

Review actual rendered hierarchy, readable contrast, full text and focus/control access at 960×540, fitted 1920×940 and 390×844, including text enlargement and no JavaScript. Compare entrance widths, padding, type and information order across all topics. Check genuine document/inner extents rather than masking overflow. Source correctness, learner comprehension and publication approval remain separate from these UI checks.
