# Local content studio

Run `pnpm studio` and open `http://127.0.0.1:4180`. Studio is a private, loopback-only authoring/review tool outside the public reader asset roots and catalog. It has no publication action and does not launch Codex or another agent runtime. `STUDIO_PORT` and `STUDIO_DATA_DIR` configure the server.

## Working contract

The initial manuscripts are binary relations, Monty Hall with an abbreviated statement missing the host policy, and the two-child observation problem. They are editable draft manuscripts/storyboards, not approved publications. [examples.ts](examples.ts) owns their initial goals, source locators, bounded claims, concept introductions, planned video durations and visual descriptions. Source consultation is not frozen-byte verification, rights clearance or expert approval.

Edit the overall brief or selected slide, then save before changing content, exporting a packet or starting a build action. Each slide has an editable learning-intent record: content references, prerequisites, a concrete success check, representation rationale, and either an interaction declaration or a reasoned static choice. Legacy slides without that record remain explicitly `unplanned` and block production/review readiness until an author supplies it; Studio does not derive intent from titles, narration or old review prose. Optimistic revisions reject stale saves. Initial-draft restoration is explicit. The editor can clone a draft under a new stable content/domain ID, edit full brief/source/claim JSON and policy selection, and add, reorder or delete slides while preserving references. New slides begin unplanned. Existing export still returns the complete local topic state; it does not publish or overwrite canonical article content.

## External-agent handoff

Studio uses files rather than an embedded chat:

1. Prepare the isolated workspace. Studio displays its absolute directory and branch.
2. Export an **implementation packet**. It binds the saved plan and feedback to the current revision, includes the selected policy checks, the machine-readable representation-selection policy and author-role expectations, and names the exact workspace directory, branch and reader route. Give that JSON file to OpenCode or another external agent and instruct it to work only in that directory.
3. Return to Studio, inspect the worktree changes, and import the packet’s completed implementation-result JSON. Studio validates the exact current topic revision/workspace and computes a source fingerprint at import. This user acknowledgement does not prove the reported checks ran and is not review, approval or publication evidence. Later source changes no longer inherit that revision linkage.
4. Export an **independent review packet** for a separate reviewer. It contains every required target (`overall` plus each slide), evaluator-role expectations, reusable policy checks, the same machine-readable representation-selection policy, the saved plan/feedback and a result contract. Every objective, reasoning, representation, interaction, rendered-surface and source assessment starts `unverified`; the template does not imply approval.
5. Import the reviewer’s JSON result with reviewer identity, review time, evidence notes and artifact references. Each target must assess all six dimensions exactly once using `adequate`, `revise`, `blocking`, `unverified` or narrowly permitted `not-applicable`. Every current assessment records `expected`, `actual`, typed `evidenceRefs`, `requestedCorrection` and `invariant`. Objective, reasoning and source are never not-applicable. A rendered-surface adequate judgment needs the checked build identity, viewport and inspected artifact reference; a source adequate judgment needs a checked source ID from the plan. Interaction can be not-applicable only for a slide with authored reasoned-static intent. Studio rejects unknown protocols, another topic/revision, missing or duplicate targets or dimensions, generic prose-only assessment rows, unknown evidence kinds, unknown source identities, invalid slide references, invalid severities and malformed timing evidence. A plan edit makes an older result stale.

The current packet protocol is `studio-external-handoff-v2` in [handoff.ts](handoff.ts); v1 result files are historical and cannot be imported as current evidence. [representation-policy.ts](representation-policy.ts) limits packet choices to DOM, SVG, Canvas 2D and WebGL 2 according to explanatory need. It requires registered adapters rather than executable manuscript payloads, model- or authored-data-backed geometry, deterministic state, declared fallbacks and limits, accessible explanatory alternatives, resource disposal and WebGL GPU-unavailable/context-loss handling. This packet-only contract does not migrate saved plans or install a universal renderer. Findings remain correction records alongside the dimension assessments; an empty findings array is not approval. Timing remains estimated/unverified without actual audio/video observation. Imported provenance is visibly recorded as a user assertion. Evidence references may describe claimed execution, but Studio does not convert them into execution verification. Studio validates supplied structure and displays provenance, but it cannot establish truthful evidence, reviewer independence, learner understanding, source correctness, rendered usability or that an independent run occurred. The reviewer cannot resolve human feedback. Imported review readiness remains separate from content/expert/rights approval and publication.

The retired embedded-chat source and HTTP actions are absent. Existing ignored `chats.json` files are deliberately left untouched so prior local histories are not destroyed; Studio no longer reads, displays or modifies them. Historical review jobs in `state.json` remain visible. Reports saved before dimension assessments existed retain their original summary, findings and timing, with no fabricated assessment migration; they cannot satisfy the current gate. Pending jobs from an older runtime are marked interrupted on restart and are never replayed.

## Review and state safeguards

[contracts.ts](contracts.ts) owns reusable narrative/claims/timing, formal-model and observation-process policies; [quality-contract.ts](quality-contract.ts) owns per-slide intent and structured assessment boundaries. Review revisions cover the complete plan, policy set, packet protocol and related base-rates source. Readiness requires authored intent for every slide, a current imported report for every target, exactly one structured and evidenced assessment for every required dimension, only `adequate` or permitted reasoned `not-applicable` verdicts, no blocking findings, no unresolved user feedback/questions and a slide total within the shared video budget. Missing intent/assessments and `revise`, `blocking` or `unverified` verdicts keep the gate not ready. Historical reports retain their original fields and provenance, remain visible, and never gain readiness through migration. Warnings remain visible.

Validated plans, feedback and imported reports live in ignored `artifacts/studio/state.json` through atomic replacement. The server binds only to loopback, rejects foreign Host/Origin writes, bounds JSON payloads, validates typed actions and exposes no shell or agent endpoint. One server owns one data directory.

## Production workspace and build

The production pane creates one isolated Git worktree per content from committed `HEAD` under ignored `artifacts/studio-workspaces/`, on a `studio/…` branch. Uncommitted host edits are not copied. A new manuscript needs authored intent for every slide before preparation creates any workspace or runs commands; incomplete drafts remain editable. Preparation projects the manuscript once into topic-owned article/claims/page sources plus a linked `slide-plan.json` preserving its supplied intent. Already registered canonical topics may still be isolated for inspection without regenerating their accepted sources; absent legacy intent keeps quality readiness blocked rather than preventing technical inspection. Existing workspace sources are never overwritten by plan saves or repeated preparation.

General import of canonical articles into Studio plans, nested-catalog recognition during existing-topic preparation, and bidirectional manuscript synchronization remain planned. Additional registered series are currently authored directly in OpenCode from their topic-owned sources and the `content:review` packet. A failed existing-topic identity/registration check must be resolved explicitly rather than bypassed by regenerating accepted sources.

Studio itself only performs bounded host-owned actions: prepare the worktree, install the registered topic figures, install the registered interactions, inspect Git status/diff, and build. Arbitrary implementation is done externally from the exported packet. The build action runs strict type checking, repository validation and the actual static builder. It fingerprints sources before/after, rejects linked output, preserves the last successful snapshot after failure and never changes the host catalog or public build output.

Snapshots are immutable local artifacts served from separate loopback origins and shown in a sandboxed iframe. Build feedback records snapshot ID, source fingerprint and Studio-selected slide. The preview origin has no Studio write API. Worktrees, snapshots and logs remain local; automatic archival and quotas remain future work.

## Metadata, figures and interaction

Format, depth and purpose are independent. Shared video budgets begin at 180 seconds for short and 900 seconds for long content; they apply only to video playback. Web reading and interaction are self-paced. Existing plans missing metadata receive the narrow legacy migration; malformed edited metadata is rejected.

[visuals.ts](visuals.ts) and the versioned figure patches install only registered, original topic-owned SVG teaching artwork without overwriting changed human assets. That SVG action does not create Canvas 2D or WebGL 2 scenes and is not a generic GPU installer. [install-interactions.ts](install-interactions.ts) installs registered deterministic reader adapters while preserving prose, scene IDs and artwork. Neither action establishes independent content review, source/rights verification or measured narration pacing. Build remains a separate explicit action.

## Layout and verification

[DESIGN.md](DESIGN.md) records the extracted design system. The document owns vertical scroll; logs, slide navigation and the preview own only their bounded directions. Narrow layouts stack, and navigation, packet controls, save, feedback and build actions remain reachable.

Run `pnpm typecheck`, `pnpm validate`, `pnpm test` and `pnpm test:studio`. The normal `pnpm test:ui` also includes Studio. Browser tests exercise packet export/import, removed chat endpoints, authoring persistence, real isolated builds and desktop/narrow/960×540 layouts. Controlled review JSON explicitly supplies protocol-fixture assessments; it is not editorial evidence and cannot prove the judgments truthful. Public static build tests must continue to exclude Studio assets, manuscripts and runtime state.
