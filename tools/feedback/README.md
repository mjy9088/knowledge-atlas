# Asynchronous question inbox

This small development-only service lets the user answer genuine editorial questions later without blocking ongoing work. It is separate from Studio, never grants agent execution permissions, and is excluded from the public static build. Current capability and preview URLs, launch commands and local admin access belong in ignored `.local/README.md`, not this tracked document.

Run `node --import tsx tools/feedback/server.ts` with distinct URL-safe `FEEDBACK_ADMIN_TOKEN` and `FEEDBACK_ANSWER_TOKEN` values of at least 24 characters. `FEEDBACK_DATA_DIR` defaults to `.local/feedback`; `FEEDBACK_PORT` defaults to 4182. The service binds loopback. An explicitly configured development gateway may forward it externally. Expose only this answer service and static previews, not Studio's write APIs.

The capability URL `/a/<answer-token>` loads questions and can submit or edit answers. Keep it private and retain its complete path when sharing with the intended respondent. The host root shows only a text access guide, never a token, question list or automatic private redirect; invalid capabilities remain unavailable. Admin bearer access can list/add questions; answer capability access cannot add questions, access arbitrary files, run commands or approve content. Browser writes require same-origin JSON plus capability header. Bodies and stored values are bounded; HTML is rendered as text. Question data uses atomic file replacement and validates on reload. One process owns a data directory. Tokens, state and logs must stay ignored. The service is a private single-user review utility, not a hardened public account system.

For agents, the authenticated local `GET /api/questions` lists pending/answered questions, and `POST /api/questions` accepts `{ "text": "...", "optional": true }`. The respondent uses the web page. Record an explicit reversible default in the question and continue non-conflicting work. A skipped question is not consent. Never put synthetic QA answers into real editorial questions or interpret agent smoke input as a user preference. Check for real answers at meaningful iteration boundaries rather than busy polling.

Use `node --import tsx --test tools/feedback/tests/feedback.test.ts tools/feedback/tests/feedback-browser.test.ts` from the project root for persistence, HTTP boundaries and actual browser submission against isolated agent-QA state. Install Playwright Chromium and a real CJK font as described in [Development](../../docs/DEVELOPMENT.md). The browser case covers reload, keyboard editing, submitting/error states, sibling-draft preservation and narrow layout. Browser evidence belongs in ignored `test-results/`; local service URLs belong in `.local/README.md`. Server lifetime is limited to the active container; restart and re-expose when necessary.
